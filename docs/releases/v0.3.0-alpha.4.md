# ConnectX v0.3.0-alpha.4 — Repeated Restricted-network Evidence

> Preview/Lab release. This version does not route ordinary application traffic and does not claim a universal DPI bypass.

## Added

- target presets for Telegram, YouTube and Discord plus a custom validated hostname;
- three BASELINE, three STRATEGY and three RECOVERY connections per run;
- quorum policy requiring two successes with at most one failure per phase;
- restricted-baseline evaluation for `baseline unavailable → strategy available → recovery unavailable`;
- explicit unstable-environment and strategy-did-not-help outcomes;
- per-phase success/failure counters and median latency;
- updated redacted report format;
- Android regression covering two sessions and eighteen TUN/relay TCP flows.

## Fixed

- strategy and recovery are no longer skipped when baseline is unavailable;
- a temporary baseline failure is no longer accepted unless recovery reproduces it;
- application and native bridge metadata now identify alpha.4.

## Network and privacy boundary

- client route remains only `192.0.2.0/24`;
- no `0.0.0.0/0` or `::/0`;
- ordinary application traffic is not routed or modified;
- one validated hostname, one pinned public IPv4 and TCP/443;
- no HTTP, login, cookie, token, response body or private API;
- no MITM, HTTPS decryption, user CA or certificate interception;
- no remote ConnectX server;
- shared reports redact hostname and resolved IPv4.

## Meaning of a positive result

`STRATEGY_RESTORED_RESTRICTED_BASELINE` means repeated baseline and recovery attempts failed while repeated split attempts returned a bounded TLS handshake/alert header in the current network. It is stronger evidence than a single attempt, but it does not prove packet boundaries or effectiveness in another network.

## Required verification before publication

The exact release commit must pass Go lock tests, native builds, JVM tests, lint, APK payload checks and Android 35 x86_64 gates for strategy foundation, TLS split, strategy evaluation, repeated external evidence, JNI lifecycle, TCP, UDP and DNS.
