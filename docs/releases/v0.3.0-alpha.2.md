# ConnectX v0.3.0-alpha.2 — Premium UI and Strategy Evaluation

This prerelease combines the bounded A/B/A strategy evaluator with a complete Compose interface redesign based on the supplied `connectx-premium-ui.zip` specification and PNG design system.

## Premium UI redesign

The previous single-screen diagnostics dump has been replaced with a structured premium dark interface:

- exact product palette based on `#07090D`, `#0E1117`, `#131720`, `#8B5CF6`, and `#7C3AED`;
- consistent system sans-serif typography so device-level decorative fonts do not replace the product UI style;
- thin borders, 14–18 dp card radii, 48 dp touch targets, and edge-to-edge layout;
- bottom navigation with **Главная**, **Маршруты**, **Статистика**, **Логи**, and **Настройки**;
- dedicated screens for mode selection, strategy selection, diagnostics, quick actions, and About ConnectX;
- reusable Compose components and OFF, ACTIVE, and ERROR previews.

### Real production bindings

The redesigned UI keeps the existing one-way state flow and uses real `ConnectionUiState` data for:

- `OFF`, `PERMISSION_REQUIRED`, `STARTING`, `LOCAL_TUN_ACTIVE`, `STOPPING`, and `ERROR` states;
- the main start/stop action through the production lifecycle callback;
- native bridge availability, version, and ABI;
- TCP, UDP, DNS, TLS write-split, and A/B/A TEST-NET actions;
- byte, latency, and relay counters from the latest completed Lab check;
- a safe state-derived log summary without packet contents, URLs, query parameters, tokens, or credentials.

### Explicit UI-preview boundary

The following screens are implemented as UI-ready previews but are not connected to the native service or persistent repositories:

- Smart, Balanced, Speed, Stability, and Custom modes;
- Auto, Strategy A, Strategy B, and Strategy C selection;
- per-app routing for Telegram, YouTube, ChatGPT, Chrome, Google Play services, and Android System;
- domain routing;
- ordinary application traffic statistics and protocol distribution;
- persistent logs, DataStore-backed settings, update actions, and accent selection.

The UI labels these areas as preview. They do not change network behavior and are not presented as completed engine functionality.

The mock values from the starter design, such as `128 MB`, `312 MB`, and `236 connections`, are not shown as production facts. Missing ordinary-traffic telemetry is represented by `—` with an explanatory message.

## Strategy evaluation core

- pure Kotlin `StrategyHealthEvaluator`;
- typed `BASELINE`, `STRATEGY`, and `RECOVERY` phases;
- bounded success/failure samples without payload, URL, DNS-name, credential, or user-identifier data;
- deterministic decisions: `KEEP_FOR_LAB_SESSION`, `ROLLBACK_CONFIRMED`, `REJECT_BASELINE_UNHEALTHY`, `REJECT_ENVIRONMENT_UNSTABLE`, and `INCONCLUSIVE`;
- overflow-safe median-latency comparison with relative and absolute regression budgets;
- immutable session gate with `READY`, `EVALUATING`, `LAB_APPROVED`, `COOLDOWN`, and `DISABLED` states;
- fixed cooldown after rollback, rejection, interruption, setup failure, or unsafe teardown;
- stale verdict and phase evidence clearing on new runs and failure paths.

## Android A/B/A Lab

A dedicated `ConnectXStrategyEvaluationService` runs:

```text
BASELINE: complete synthetic ClientHello → one write()
STRATEGY: same ClientHello → tls-clienthello-split-v1 → two ordered write()
RECOVERY: same ClientHello → one write()
```

Each phase uses a separate TCP connection through:

```text
192.0.2.1:18444
→ Android TEST-NET TUN
→ native gVisor/tun2socks stack
→ authenticated local SOCKS5 relay
→ protected loopback echo endpoint
```

The evaluator verifies byte-identical echo data, per-phase generation, latency, relay byte deltas, connection deltas, teardown, late-stop idempotence, and explicit restart behavior.

## TLS ClientHello validation

The Lab runtime uses one shared structurally complete 50-byte TLS ClientHello fixture:

- TLS 1.2 legacy record and ClientHello versions;
- 32-byte random;
- empty session id;
- one cipher suite;
- one null compression method;
- no SNI, host name, URL, credential, or external identifier.

The inspector validates record and handshake lengths, session-id bounds, a non-empty even cipher-suite vector, compression methods, and optional extension boundaries. The old 44-byte prefix-only fixture is rejected as `MALFORMED_LENGTH`.

The deterministic split remains at offset `43`, producing segments `[43, 7]` with byte-identical reconstruction.

## Safety boundary

- TUN capture remains limited to TEST-NET-1 (`192.0.2.0/24`).
- The A/B/A target is exactly `192.0.2.1:18444` and is rewritten only to a loopback endpoint.
- No default IPv4 or IPv6 route is installed.
- Ordinary application traffic is not intercepted, evaluated, or modified.
- YouTube, Telegram, ChatGPT, and other application traffic are not claimed to be bypassed by this version.
- No external domain, resolver, or remote ConnectX server is contacted.
- No MITM, HTTPS decryption, custom certificate, or user CA is used.
- Two socket `write()` calls are not described as two TCP packets on the wire.
- A successful local A/B/A result is not evidence of working DPI bypass on a real restricted network.
