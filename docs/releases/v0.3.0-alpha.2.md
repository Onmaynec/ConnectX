# ConnectX v0.3.0-alpha.2 — Strategy Evaluation and Rollback Gate

This prerelease adds a measurable local health gate around the first lab-only TLS write-split strategy.

## Added

- pure Kotlin `StrategyHealthEvaluator`;
- typed `BASELINE`, `STRATEGY`, and `RECOVERY` phases;
- bounded success/failure samples without payload, URL, DNS, or credential data;
- deterministic decisions and reason codes;
- overflow-safe latency regression calculation;
- immutable session gate with `READY`, `EVALUATING`, `LAB_APPROVED`, `COOLDOWN`, and `DISABLED` states;
- 60-second cooldown after rollback, rejection, interruption, setup failure, or unsafe teardown;
- dedicated `ConnectXStrategyEvaluationService`;
- three separate TCP connections over the real Android TEST-NET TUN path;
- one-write baseline, two-write strategy, and one-write recovery;
- byte-for-byte echo validation in every completed phase;
- per-phase latency and typed failure diagnostics;
- total relay byte and connection evidence;
- idempotent late-stop handling after a completed evaluation;
- immediate explicit re-evaluation remains possible after a successful teardown;
- Compose action and result presentation for strategy evaluation;
- JVM boundary tests, reducer tests, and Android instrumentation gate.

## TLS ClientHello validation

The Lab runtime now uses one shared, structurally complete 50-byte TLS ClientHello fixture:

- TLS 1.2 legacy record and ClientHello versions;
- 32-byte random;
- empty session id;
- one cipher suite;
- one null compression method;
- no SNI, host name, URL, credential, or external identifier.

The bounded inspector validates exact record and handshake lengths, session-id bounds, a non-empty even cipher-suite vector, a non-empty compression-method vector, and optional extension boundaries. The old 44-byte prefix-only fixture is rejected as `MALFORMED_LENGTH`.

The deterministic split remains at offset `43`, creating segments of 43 and 7 bytes. The one-shot TLS Lab and the A/B/A evaluator use the same builder. Android evidence for a completed evaluation therefore requires three distinct connections and at least `3 × 50` bytes in each direction.

TLS legacy-version regression coverage distinguishes the major and minor bytes explicitly: structurally valid TLS 1.1 legacy version `0x0302` remains accepted, while `0x0304` is rejected as a ClientHello legacy-version code.

## Decision semantics

- `KEEP_FOR_LAB_SESSION` means only that the local synthetic A/B/A check completed within the fixed health budget.
- `ROLLBACK_CONFIRMED` means baseline and recovery were healthy while the strategy failed or regressed beyond the allowed latency.
- `REJECT_BASELINE_UNHEALTHY` avoids blaming the strategy when the path was already unhealthy.
- `REJECT_ENVIRONMENT_UNSTABLE` prevents approval when recovery is unhealthy.
- `INCONCLUSIVE` prevents approval when bounded evidence is insufficient.

A completed evaluation is not automatically a successful strategy. The UI displays execution success separately from the evaluator decision.

## State and UI hardening

- decision/reason pairs are validated exhaustively;
- latency evidence is present only for keep and latency-regression reports;
- failure-reason counters are immutable through the JVM API;
- cooldown expiry, approved-session reset, and disable clear stale decisions;
- non-initial session-gate states cannot be constructed by external Kotlin modules;
- starting a new strategy run clears the previous verdict, phase latency, byte evidence, and gate state;
- a failed new run cannot display evidence from an older successful evaluation.

## Safety boundary

- Android route remains only `192.0.2.0/24`.
- The A/B/A target is exactly `192.0.2.1:18444` and is rewritten only to a loopback echo server.
- No default IPv4 or IPv6 route is installed.
- No ordinary application traffic enters the strategy path.
- No external domain, resolver, or ConnectX server is contacted.
- No MITM, HTTPS decryption, certificate installation, or user CA is used.
- The strategy remains `LAB_ONLY` and requires an explicit user action.
- Two `write()` calls are not described as two TCP packets.

## Validation performed locally

Independent pure-Kotlin smoke gates confirm:

- complete payload size: `50` bytes;
- split offset: `43`;
- segments: `[43, 7]`;
- byte-identical reconstruction;
- old prefix-only fixture rejection;
- TLS 1.1 legacy-version acceptance;
- `0x0304` ClientHello legacy-version rejection.

These checks do not replace the Gradle, lint, APK, or Android device gates.

## Validation required before publication

The prerelease workflow must pass on the exact release commit:

- committed Go dependency lock verification;
- native bridge build for `arm64-v8a` and `x86_64`;
- all JVM tests;
- Android lint;
- debug APK build and legal payload verification;
- strategy foundation Android gate;
- TLS write-split TUN Android gate using the complete 50-byte fixture;
- new A/B/A strategy evaluation Android gate with `3 × 50` byte evidence;
- late-stop idempotence and immediate restart regression;
- JNI lifecycle gate;
- TCP, UDP, and DNS regression gates;
- generation-safe teardown with the native stack stopped at the end.

The implementation PR only installs the guarded release workflow. A separate post-merge marker PR activates publication after that workflow is already present in `main`; the implementation merge itself does not publish the prerelease.

## Evidence status

Android runs created before the complete ClientHello fixture used the old 44-byte prefix-only payload. They remain useful historical evidence for TUN, JNI, relay, and teardown behavior, but they do not validate the current strict parser or the current 50-byte TLS runtime path.

The current exact heads must receive fresh build, lint, APK, JVM, and Android runtime results before either implementation PR can be marked ready or merged.

## Known limitations

- This is a diagnostic prerelease, not a production traffic bypass.
- The Android Lab uses one sample per phase and a synthetic TLS ClientHello.
- No real restricted-network or ISP evidence is included.
- No application-specific compatibility claim is made.
- GitHub-hosted runners must be available before the final commit can be verified, merged, tagged, or published.

See `docs/architecture/strategy-evaluation.md` for the complete evaluation model and boundaries.
