# ConnectX v0.3.0-alpha.3 — Restricted-network TLS Evidence Lab

> Preview/Lab release. This version does not claim a universal or production-ready DPI bypass.

## Added

- manual evidence dialog for one hostname;
- strict IDN/STD3 hostname normalization;
- fixed target port `443`;
- rejection of URL, IP literal, credentials, path and reserved local names;
- one-time DNS resolution with deterministic pinned public IPv4;
- rejection of private, loopback, link-local, CGNAT, benchmark, documentation, multicast and reserved IPv4 ranges;
- rejection of mixed public/private DNS answers;
- local `SSLEngine` ClientHello generation with SNI;
- reuse of the existing bounded ClientHello inspector and `tls-clienthello-split-v1` planner;
- baseline → split → recovery evaluation through a real Android `VpnService` and TEST-NET TUN;
- reading only the first five bytes of the returned TLS record header;
- phase latency, record kind, decision, reason and session-gate diagnostics;
- deterministic loopback TLS-like responder for Android instrumentation;
- debug-only test override that release APKs reject before opening TUN or relay resources.

## Network and privacy boundary

- the client route remains only `192.0.2.0/24`;
- no `0.0.0.0/0` or `::/0` route is installed;
- only one manually supplied hostname is checked;
- only TCP/443 is allowed in production evidence mode;
- the outbound relay socket is protected with `VpnService.protect()`;
- no HTTP request, login, cookie, token or response body is sent or read;
- no MITM, HTTPS decryption, user CA or certificate interception;
- no remote ConnectX server;
- payload and SOCKS credentials are not written to runtime logs.

## What the result means

A successful phase means the current network returned a bounded TLS `handshake` or `alert` record header after receiving the generated ClientHello. The A/B/A evaluator can keep the strategy for the current Lab session, confirm rollback, reject an unhealthy baseline or mark the environment unstable.

The result does not prove that two socket writes became two TCP/IP packets. It also does not prove that the strategy bypasses every DPI implementation or works in another network.

## Validation required before publication

The tag and GitHub prerelease must not be created until the exact release commit passes:

- committed Go dependency lock and native bridge tests;
- native builds for `arm64-v8a` and `x86_64`;
- all JVM/unit tests, including target policy, ClientHello factory, TLS prefix classifier and deterministic responder;
- Android lint and APK assembly;
- APK native/legal payload checks;
- Android strategy foundation and local TLS split gates;
- Android local A/B/A rollback gate;
- Android external TLS evidence gate with real TUN/native/relay lifecycle;
- JNI, TCP, UDP and DNS regression gates;
- teardown assertions proving that the native stack is stopped.

## Current infrastructure limitation

At the time these notes were written, GitHub hosted jobs were ending before `Checkout` with no steps or logs. The implementation therefore remains a draft stacked PR and is not eligible for merge or publication until hosted runners execute the complete final gate.
