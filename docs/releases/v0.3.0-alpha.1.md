# ConnectX v0.3.0-alpha.1 — Strategy Foundation and TLS Write-Split Lab

## Что добавлено

Эта версия создаёт первый подключаемый слой стратегий ConnectX и проверяет одну минимальную lab-стратегию через существующий локальный TUN-конвейер.

### Strategy API

- отдельный pure Kotlin модуль `:strategy:api`;
- типизированный `BypassStrategy` contract;
- capability model для TCP, UDP, IPv4, IPv6, TLS, QUIC и root;
- canonical strategy identifiers;
- immutable registry с запретом повторяющихся id;
- отдельные `LAB_ONLY` и `USER_TRAFFIC` scopes;
- глобальный feature gate, выключенный по умолчанию;
- типизированные причины отказа вместо скрытого fallback.

### `tls-clienthello-split-v1`

Первая встроенная стратегия принимает только ограниченный синтетический TLS ClientHello и строит план двух последовательных socket writes.

Единый Lab fixture имеет размер 50 bytes и содержит TLS 1.2 legacy version, 32-byte random, empty session id, одну cipher suite и null compression method. Он не содержит SNI, домен, URL, credential или внешний идентификатор.

Перед созданием плана bounded inspector проверяет:

- TLS handshake content type;
- допустимую TLS record и ClientHello legacy version;
- тип ClientHello;
- exact record и handshake lengths;
- session-id vector и предел 32 bytes;
- непустой чётный cipher-suite vector;
- непустой compression-method vector;
- границы optional extensions;
- минимальный и максимальный размер;
- отсутствие trailing data;
- что payload ещё не обрабатывался;
- что execution scope равен `LAB_ONLY`.

Прежний 44-byte prefix-only fixture не являлся полным ClientHello и теперь отклоняется как `MALFORMED_LENGTH`.

План хранит defensive copies сегментов и обязан восстановить исходный ClientHello байт-в-байт. Split offset `43` создаёт сегменты 43 и 7 bytes.

### Android TLS write-split Lab

По отдельной кнопке приложение выполняет путь:

```text
Complete 50-byte synthetic TLS ClientHello
  → 2 ordered Android socket write() calls
  → 192.0.2.1:18443
  → TEST-NET TUN
  → gVisor/tun2socks
  → authenticated local SOCKS5 relay
  → protected 127.0.0.1 echo endpoint
```

Loopback endpoint возвращает собранный TCP stream. Успех засчитывается только когда:

- strategy planner создал ровно два непустых сегмента;
- reconstructed planner payload совпал с исходным;
- полный stream прошёл через Android TUN и native stack;
- echo payload совпал байт-в-байт;
- relay подтвердил соединение и не менее 50 bytes в каждом направлении;
- после завершения native stack, TUN, socket, relay и endpoint закрылись.

В интерфейсе отображаются strategy id, число write-сегментов, split offset, latency, bytes и relay connections.

## Проверки выпуска

Guarded release выполняет на точном merge commit:

1. committed Go dependency lock и bridge tests;
2. native build для `arm64-v8a` и `x86_64`;
3. strategy API, parser, registry и reducer JVM tests;
4. Android lint и APK payload verification;
5. Android 35 x86_64 strategy-foundation instrumentation test;
6. Android foreground `VpnService` TLS write-split TUN gate с полным 50-byte fixture;
7. packaged JNI lifecycle gate;
8. существующие TCP, UDP и DNS TUN gates;
9. отдельный app/VPN teardown между runtime gates.

## Статус доказательств

Предыдущий успешный Android run выполнялся до исправления структуры fixture и использовал 44-byte prefix-only payload. Он остаётся полезным evidence для TUN/JNI/relay lifecycle, но **не подтверждает текущую строгую ClientHello validation и новый 50-byte runtime path**.

Для текущего head обязательны повторные JVM, build, lint, APK и Android runtime gates. До их успешного выполнения alpha.1 остаётся draft и не публикуется.

## Граница подтверждения

Два вызова `SocketOutputStream.write()` **не являются доказательством двух TCP-сегментов или двух IP-пакетов на проводе**. Android, gVisor или другой слой может объединить записи.

Эта версия подтверждает только после успешного exact-head gate:

- безопасность и ограниченность planner;
- выключенный по умолчанию feature gate;
- невозможность применения первой стратегии к `USER_TRAFFIC` scope;
- корректную передачу неизменённого TCP stream через локальный TUN path.

Эта версия не подтверждает:

- фактические packet boundaries;
- эффективность против конкретной DPI-системы;
- работу на ограниченной сети;
- готовность стратегии для обычного пользовательского трафика.

## Безопасность и приватность

- TUN route остаётся только `192.0.2.0/24`;
- strategy target ограничен точной парой `192.0.2.1:18443`;
- endpoint и relay слушают только `127.0.0.1`;
- `0.0.0.0/0` и `::/0` не добавляются;
- системный DNS не перехватывается;
- внешний resolver не используется;
- HTTPS не расшифровывается;
- пользовательские сертификаты не устанавливаются;
- TLS payload, DNS names, URL, credentials и содержимое трафика не логируются;
- удалённый ConnectX server отсутствует;
- root не используется.

## Известные ограничения

- strategy feature gate доступен только внутри явного lab probe;
- нет packet capture, подтверждающего transport segmentation;
- нет обработки реальных доменов или аккаунтов;
- нет IPv6 и QUIC strategy support;
- native transport bridge сохраняет версию `0.2.0-alpha.6`, поскольку его код в этом релизе функционально не изменялся;
- рабочий обход блокировок не заявляется.
