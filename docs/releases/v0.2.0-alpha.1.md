# ConnectX v0.2.0-alpha.1 — TCP Engine Preview

Первая alpha-сборка сетевого движка ConnectX.

## Что добавлено

- локальный SOCKS5 `CONNECT` relay на loopback-интерфейсе;
- обязательная случайная SOCKS5-аутентификация, создаваемая заново при каждом запуске;
- прямые исходящие TCP-соединения к настоящим серверам назначения;
- обязательный вызов `VpnService.protect()` до подключения исходящего сокета;
- ограничение числа одновременных соединений;
- двусторонняя передача данных;
- счётчики соединений и переданных байтов;
- unit-тесты SOCKS5, включая отказ при неверном токене;
- end-to-end тест relay через локальный echo server;
- архитектурное решение по tun2socks/gVisor;
- обновлённый экран статуса `Engine alpha`.

## Важное ограничение

Это ещё не рабочий обход блокировок.

В alpha.1 локальный TCP relay уже работает и тестируется, но обычный трафик Android пока не подключён к нему. TUN продолжает перехватывать только зарезервированную тестовую сеть `192.0.2.0/24`.

Следующий этап — собрать tun2socks/gVisor из исходников, передать ему TUN fd и соединить его с локальным relay. Только после проверки этого моста можно безопасно включать маршрут `0.0.0.0/0`.

## Пока не поддерживается

- UDP;
- DNS passthrough;
- IPv6;
- QUIC/HTTP3;
- DPI-обфускация;
- автоматический подбор стратегий.

## Приватность и защита локального relay

- удалённый VPN или proxy-сервер ConnectX не используется;
- SOCKS endpoint слушает только loopback на случайном порту;
- подключение требует случайный секрет, который хранится только внутри процесса и не выводится в UI или логи;
- исходящий сокет не создаётся при ошибке аутентификации;
- HTTPS не расшифровывается;
- сертификаты не устанавливаются;
- содержимое трафика не журналируется.

## Совместимость

- Android 10 и новее;
- debug APK для тестирования;
- установка поверх v0.1.0 поддерживается благодаря увеличенному `versionCode`.
