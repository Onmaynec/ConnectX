# ConnectX v0.3.0-alpha.6 — Evidence Quality Gate

`v0.3.0-alpha.6` improves how repeated TLS strategy evidence is interpreted and shared. It does not expand routing or claim a universal bypass.

## Added

- Pure Kotlin evidence assessor with four explicit classes:
  - `STRATEGY_HELP_CONFIRMED`;
  - `AVAILABLE_WITHOUT_STRATEGY`;
  - `STRATEGY_NOT_HELPFUL`;
  - `INCONCLUSIVE`.
- `HIGH`, `MEDIUM` and `LOW` confidence derived from complete 3×A/B/A sample consistency.
- Safe next-action recommendations that never enable the strategy automatically.
- Redacted report schema v2 with deterministic 24-hex `report_id`.
- Allow-list report validator that rejects unknown fields, raw IPv4, URLs and credential-like fragments.
- UI lines for evidence class, confidence and recommended next step.
- Unit tests for confirmed restricted evidence, ordinary availability, regression, incomplete samples, deterministic IDs and unsafe report mutations.

## Validation

The release remains gated by:

- release manifest and negative provenance tests;
- all JVM unit tests;
- Android lint;
- debug APK and legal/native payload checks;
- Android 35 strategy, repeated evidence, JNI, TCP, UDP and DNS runtime gates.

## Safety boundary

- Only TEST-NET-1 is routed through the lab TUN.
- Ordinary application traffic is not processed.
- No HTTP request, response body, account login, token, cookie, MITM, user CA or HTTPS decryption.
- The report does not receive hostname, resolved IPv4, payload or raw exception text.
- A positive result is network-specific evidence for manual review, not automatic activation or a universal bypass claim.
