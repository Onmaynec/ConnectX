# ConnectX v0.2.0-alpha.4 — Bounded TCP Path Probe

Alpha.4 впервые проверяет реальный TCP-путь через Android TUN и source-built native stack, не включая маршрутизацию обычного интернета.

## Что добавлено

- отдельная кнопка `Проверить TCP-путь через TUN`;
- новый типизированный режим `native_tcp_probe`;
- process-local TCP echo endpoint на `127.0.0.1`;
- exact relay override только для `192.0.2.1:18080`;
- передача TEST-NET TCP-потока через Go/gVisor и tun2socks;
- authenticated SOCKS5 relay с обязательным `VpnService.protect()` для outbound socket;
- случайный 64-байтовый nonce и проверка точного echo-ответа;
- отображение задержки, upload/download bytes и числа relay connections;
- автоматическая очистка probe socket, native stack, TUN, relay и echo endpoint;
- полный Android emulator gate, который выдаёт тестовому приложению VPN app-op и запускает реальный `VpnService` probe.

## Как проходит проверка

```text
Android probe socket
  → маршрут 192.0.2.0/24
  → Android TUN
  → fd-backed Go/gVisor stack
  → tun2socks SOCKS5 CONNECT
  → authenticated relay на 127.0.0.1
  → exact override 192.0.2.1:18080
  → bounded loopback echo server
  → тот же путь обратно
```

Probe считается успешным только если:

1. echoed nonce полностью совпал;
2. native bridge оставался в состоянии running во время обмена;
3. relay подтвердил минимум одно соединение;
4. upload и download counters не меньше размера nonce;
5. после результата native bridge остановлен и все descriptors закрыты.

## Исправления lifecycle

- relay и echo endpoint теперь жёстко используют IPv4 loopback `127.0.0.1`, чтобы не зависеть от Android `::1` default;
- fd-backed TUN device закрывается до `gVisor stack.Wait()`, как в upstream tun2socks engine;
- stop/revoke инвалидирует текущую generation, поэтому завершившийся позднее worker не может опубликовать устаревший success;
- repeated stop остаётся идемпотентным.

## Как проверить на устройстве

1. Установите APK поверх alpha.3.
2. Откройте ConnectX.
3. Убедитесь, что native bridge доступен и показан ABI.
4. Нажмите `Проверить TCP-путь через TUN`.
5. Подтвердите системное VPN-разрешение Android.
6. Дождитесь автоматического завершения probe.
7. Проверьте latency, upload/download bytes и relay connections в diagnostics card.
8. Повторите probe несколько раз и отдельно проверьте отмену кнопкой `Выключить`.

## Ограничения безопасности

- TUN route остаётся только `192.0.2.0/24`;
- `0.0.0.0/0` и `::/0` не добавляются;
- relay rewrite действует только для `192.0.2.1:18080`;
- relay и echo endpoint не слушают LAN-интерфейсы;
- DNS, UDP, IPv6, QUIC и DPI-обфускация отсутствуют;
- удалённые серверы ConnectX не используются;
- HTTPS не расшифровывается, сертификаты не устанавливаются;
- содержимое трафика и SOCKS credentials не выводятся;
- версия не заявляет рабочий обход блокировок.
