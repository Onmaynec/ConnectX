# ConnectX v0.2.0-alpha.6 — Bounded DNS Path Probe

Alpha.6 добавляет первый детерминированный DNS query/response через уже проверенный Android UDP path. Системные DNS-запросы и обычный интернет-трафик по-прежнему не перехватываются.

## Что добавлено

- отдельная кнопка `Проверить DNS-путь через TUN`;
- типизированный режим `native_dns_probe`;
- отдельный foreground `VpnService` для изоляции DNS lifecycle;
- строгий DNS codec с лимитом 512 байт;
- единственный разрешённый запрос `A/IN connectx.invalid`;
- случайный 16-битный transaction ID;
- фиксированный authoritative non-recursive ответ `192.0.2.42`;
- loopback responder, который никогда не обращается к внешнему resolver;
- exact-only diagnostic endpoint `192.0.2.53:53`;
- outbound UDP socket проходит `VpnService.protect()`;
- latency, bytes, associations, datagrams, queries и responses в diagnostics;
- отдельные JVM и Android runtime tests;
- native bridge version `0.2.0-alpha.6`.

## Проверяемый путь

```text
Android IPv4 DatagramSocket
  → маршрут 192.0.2.0/24
  → Android TUN
  → fd-backed Go/gVisor stack
  → tun2socks SOCKS5 UDP ASSOCIATE
  → authenticated relay на 127.0.0.1
  → exact override 192.0.2.53:53
  → protected loopback DNS responder
  → тот же путь обратно
```

Probe считается успешным только если:

1. transaction ID полностью совпал;
2. question остаётся точным `A/IN connectx.invalid`;
3. ответ содержит ровно один `A` record `192.0.2.42`;
4. native bridge получил UDP flow;
5. relay подтвердил authenticated UDP association и datagram exchange;
6. responder подтвердил query и response без rejected packets;
7. byte counters покрывают полный DNS query/response;
8. после результата native bridge, TUN, sockets, relay и responder закрыты.

## Отвергаемые пакеты

- compressed DNS names;
- несколько questions;
- типы кроме `A` и классы кроме `IN`;
- неожиданные flags или дополнительные sections;
- неверный transaction ID или адрес ответа;
- truncated, oversized и trailing data;
- любые UDP destinations кроме `192.0.2.53:53`.

## Android runtime gates

JNI, TCP, UDP и DNS tests запускаются отдельными instrumentation-сессиями. Между ними CI принудительно останавливает app/test processes, возвращает VPN app-op в исходное состояние и ждёт полного teardown. Результаты каждого gate сохраняются отдельно.

## Как проверить на устройстве

1. Установите APK поверх alpha.5.
2. Откройте ConnectX.
3. Нажмите `Проверить DNS-путь через TUN`.
4. Подтвердите системное VPN-разрешение Android.
5. Дождитесь автоматического завершения.
6. Проверьте ответ `192.0.2.42`, latency и transport counters.
7. Повторите probe и отдельно проверьте остановку кнопкой `Выключить`.

## Ограничения безопасности

- TUN route остаётся только `192.0.2.0/24`;
- `0.0.0.0/0` и `::/0` не добавляются;
- системный DNS не перенастраивается и не перехватывается;
- внешний DNS resolver не используется;
- responder и relay слушают только `127.0.0.1`;
- query names, payload и credentials не логируются;
- удалённые серверы ConnectX не используются;
- HTTPS не расшифровывается и сертификаты не устанавливаются;
- IPv6, QUIC и DPI strategies не включены;
- версия не заявляет рабочий обход блокировок.
